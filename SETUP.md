# JanaМен / JanaPost — настройка с чистого листа

Эта инструкция относится к `00_FRESH_DATABASE.sql` и **новому пустому Supabase-проекту**.
Не запускайте этот сценарий в старом проекте с нужными данными. Если в старой базе есть заявки или пользователи, сначала экспортируйте их и не удаляйте старый проект.

## 1. Создайте новый Supabase-проект

1. Откройте https://supabase.com/dashboard/ и нажмите **New project**.
2. Выберите организацию, задайте имя проекта, например `janamen-fresh`, регион и надёжный пароль базы данных.
3. Сохраните пароль базы в надёжном менеджере паролей. Он не нужен в `.env`.
4. Дождитесь, пока Supabase закончит создавать проект.

## 2. Выполните один SQL-файл

1. В новом проекте откройте **SQL Editor → New query**.
2. На компьютере откройте `supabase/00_FRESH_DATABASE.sql` из этого проекта.
3. Скопируйте весь файл в SQL Editor и нажмите **Run**.
4. Проверьте, что запрос завершился без красной ошибки.

Этот файл сначала создаёт `public.profiles` и `public.requests`, которых не хватало в старой схеме, а затем добавляет три роли, согласование, остатки отпускных дней, календарь, историю заявок, прогресс курсов и политики безопасности.

**Выполняйте именно `00_FRESH_DATABASE.sql`. Не запускайте после него отдельно `00_ALL_IN_ONE.sql` или файлы миграций по одному.**

## 3. Подключите приложение к НОВОМУ проекту

1. В корне папки `JanaMen` скопируйте `.env.example` и назовите копию `.env`.
2. В Supabase найдите URL проекта и публичный ключ (`Publishable key`, либо `anon` для legacy-проектов).
3. Заполните `.env` так:

```dotenv
VITE_SUPABASE_URL=https://YOUR_NEW_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_NEW_SUPABASE_PUBLISHABLE_KEY
```

Поставьте настоящие значения нового проекта вместо примеров. Сохраните файл. Не помещайте в него `service_role`, `sb_secret_` или Gemini API key.

## 4. Настройте URL авторизации

В Supabase откройте **Authentication → URL Configuration**. Для локальной проверки установите Site URL `http://localhost:5173` и добавьте `http://localhost:5173/**` в Redirect URLs, если используется подтверждение почты.

## 5. Запустите сайт и создайте тестовые аккаунты

В PowerShell, открытом в корне папки `JanaMen`, выполните:

```powershell
npm ci
npm run lint
npm run build
npm run dev
```

Откройте адрес, который Vite покажет в терминале (обычно `http://localhost:5173`). Сначала SQL нужно выполнить, а уже потом регистрировать аккаунты: триггер автоматически создаёт профиль с ролью `employee`.

Зарегистрируйте отдельные аккаунты для сотрудника, руководителя и HR. Если включено подтверждение почты, подтвердите её для каждого пользователя.

## 6. Назначьте роли и связи

Откройте `supabase/02_assign_roles_TEMPLATE.sql`. Замените примерные email-адреса на адреса созданных аккаунтов и выполните нужные команды в Supabase → SQL Editor.

- Сотрудник получает роль `employee`, `manager_id` — ID назначенного руководителя.
- Руководитель получает роль `manager`.
- HR получает роль `hr`.
- Для каждого сотрудника заполните `annual_leave_days_remaining` актуальным подтверждённым остатком от HR. Не используйте примерное число без проверки.

Профиль создаётся автоматически после регистрации. Если аккаунт зарегистрирован до установки SQL, проверьте наличие строки в `public.profiles`; недостающие профили нужно создать с учётом ID из `auth.users`.

## 7. Тестирование

Следуйте `TEST_ROUTE.md`: сотрудник создаёт заявку, руководитель согласовывает/отклоняет, HR принимает финальное решение. Проверяйте, что статус сохраняется после обновления страницы и оплачиваемые дни списываются только один раз после финального одобрения HR.

## Jana AI (необязательно)

Jana AI требует серверной функции `gemini-assistant` и секрета `GEMINI_API_KEY` в Supabase Edge Functions Secrets. Ключ Gemini нельзя помещать в `.env` с префиксом `VITE_` и нельзя публиковать. Новый ключ создайте в Google AI Studio, задайте как серверный секрет и разверните функцию. Основные заявки работают независимо от этого помощника.
