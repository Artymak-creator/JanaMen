# Исправления ESLint и проверка сборки

В этой версии устранены четыре ошибки `react-hooks/set-state-in-effect`:

- `src/App.tsx`: проверка изменений статусов заявок перенесена в асинхронную загрузку данных из Supabase. Эффект больше не вызывает `setNotice` напрямую; статусы в localStorage сохраняются отдельно для заявок текущего пользователя.
- `src/components/Academy.tsx`: прогресс из localStorage читается лениво при инициализации состояния, а прогресс из Supabase применяется после завершения асинхронного запроса. Компонент перемонтируется при смене пользователя.
- `src/lib/calendar.ts`: результат календарного запроса хранится вместе с ID пользователя; данные другого пользователя не отображаются. Первичная загрузка запускается в следующем microtask, чтобы эффект не мог синхронно вызвать обновление состояния.
- `src/lib/history.ts`: история хранится вместе с ID пользователя; выход из аккаунта не требует синхронного сброса состояния из эффекта, и история прошлого аккаунта скрывается.

## Проверки, выполненные в среде сборки

- ESLint: пройдено, 0 ошибок и 0 предупреждений.
- TypeScript (`tsc -b`): пройдено.
- Vite production build: пройдено.
- Vite выдал только предупреждение о размере JavaScript-чанка больше 500 kB; это предупреждение не блокирует сборку.

Проверьте на своём компьютере после `npm ci`:

```powershell
npm run lint
npm run build
npm run dev
```

Проверка реальной авторизации, SQL-миграций и трёх ролей в вашем Supabase этим набором команд не выполняется — её необходимо провести отдельно на тестовых аккаунтах.
